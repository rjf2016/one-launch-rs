# M6 Release

**Goal.** The installer, the updater and the release workflow, satisfying the takeover contract in every direction. Design: `../design/takeover.md`.

I1 to I3 and UP1 to UP2 may start any time after Milestone 1.

`E\` is the Electron repo at the pin.

## Tickets

| Ticket | Scope | Ports |
| --- | --- | --- |
| I1 | Freeze the NSIS script and defines | `E\node_modules\app-builder-lib\templates\nsis\`, `E\build\installer.nsh`, `E\electron-builder.yml` |
| I2 | Packaging in `xtask`: installer, `latest.yml`, notices | `E\scripts\third-party-notices.mjs` |
| I3 | Contract suite on hosted runners: fresh install, Electron to Rust, Rust to Rust, folder move, Run value, uninstall, Rust to Electron | new |
| I4 | Release workflow and the sign-tool port | `E\.github\workflows\release.yml`, `E\scripts\release-{sign,notes,prompt}.mjs` |
| I5 | Exe resources: icon at index 0, manifest, version info | `E\build\` |
| UP1 | Manifest parsing and key check, with a real signed `latest.yml` as a vector | `E\src\main\updates\{manifest,release-keys}.ts` |
| UP2 | Availability | `updates\availability.ts` |
| UP3 | Feed and download | `updates\engine.ts` |
| UP4 | State machine | `updates\update-service.ts` |
| UP5 | Install at quit and its blockers | `E\src\main\index.ts` quit handling |
| UP6 | Test feed and the update scenario | `updates\test-feed.ts`, `E\scripts\scenarios\update.mjs` |

Signing keys never enter the repo or a session. The key-generation and signing steps stay the owner's; the port keeps the same `latest.yml` shape so the runbook does not change.

## Exit gate

- The contract suite passes on CI in all four directions.
- The six update feed conditions from the oracle match.
- The data-folder latch is still closed in every build agents can produce.

## The owner's part

- Flip the data-folder latch.
- One real update on the real install, after copying the data folder aside: run the Rust installer exactly as the updater would.
- Tag, sign, publish.
