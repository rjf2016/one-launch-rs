# M7 Cutover

**Goal.** Prove parity as a whole, prove the "lighter and faster" claim with numbers, and move the Rust tree into the repo that existing installs update from.

## Tickets

| Ticket | Scope |
| --- | --- |
| A1 | Triage closure: every row decided and reflected in the oracle expectations |
| A2 | Full parity audit: fresh agents re-read every spec section against the Rust code; every finding becomes a fix ticket |
| A3 | Performance against the Milestone 0 baseline: start-up, memory, idle CPU, install size |
| A4 | Screen-reader pass over the AccessKit tree |
| A5 | Soak: hours of idle and repeated fake switches with no growth in memory or handles |
| A6 | The owner's real-step runbook, written as numbered steps with one expected result each |
| A7 | Rollback rehearsal on a hosted runner: Electron installer over a Rust install |
| A8 | Cutover: the Rust tree replaces the Electron tree in the old repo through one PR |

## Exit gate

- Every ledger row is covered or waived.
- All 22 replays and 30 UI scenarios match; all 174 states are within tolerance or triaged.
- The contract suite passes in all four directions.
- Performance budgets are met against the baseline.

## The owner's part

- Go/no-go.
- Open and merge the cutover PR in the old repo; tag, sign and publish from there.
- Declare the transition over when satisfied. Only then may the schema or the vault format change.
