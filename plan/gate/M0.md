## Found in Electron

`plan/gate/M0-findings.md` lists everything the captures found in the app, the plan and the design. In short:

- Three ways damaged data could hang, end or mislead the app, and several byte-exact rewriters that are not exact on odd input. The ones a user could meet are rows X-11 to X-20 above.
- One contradiction with the spec: a download whose hash does not match ends as "download failed", not "verify failed". The spec is amended (7.5 step 6).
- The design's "no elevation" is not exact for all-users installs (row X-14).
- The JavaScript behaviours a Rust port gets wrong by default (items 44 to 52 there), each with vector cases.

Every item not covered by a row is judged when its ticket is prepared; none has to be carried over only because Electron does it.

## Found at this gate

- **The commit address.** The first nine commits of this repo carried your personal email address; the public Electron repo carries your GitHub noreply address on every commit. Nothing was pushed, so on your word they were re-stamped to the noreply address (content, dates and messages unchanged), and this repo now has that address set as its own. The scan that found it is part of the verify script (`--repo`): it reads every file in this repo's history, not only the bundle, and every commit's address.
- **Roughly one replay capture in ten stops, and says why.** The app's log keeps the last four characters of an id. When two random ids of one recording end in the same four, the recorder cannot name the one in a log line and refuses the recording. It happened once here; the second run passed and matched. The app behaved the same in every recording. The Rust replay runner must not inherit this: in replay mode it takes its ids from a seeded source (for Milestone 3 ticket-prep).
- **The copy map repeats only from the same shots.** `assets/copy-map.json` and one list in `assets/copy.json` quote every text run on screen, the time-dependent ones too. Built on the second capture's sidecars, the map differs in 40 values, all inside the 23 runs the sidecars flag as time-dependent, and the list differs in the entries that come from those runs. The 2,247 source strings and the placement of every other run are identical.
- **A busy machine fails a timing test.** One Steam adapter test with a tight real-timer budget failed once while update captures ran beside it; the capture refused the run, and passed when run alone. A known weakness of those tests; nothing is retried.
