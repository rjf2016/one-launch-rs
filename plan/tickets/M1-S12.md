## Outcome

`plan/decisions/M1-S12.md`: one row per effect, each ending in equivalent, approximation or none, with the crops. `docs/cookbook/effects.md` holds what works. For each row that is not an equivalent, the record drafts a triage row; ticket-prep adds it to `plan/triage.toml` in its own pull request, and the owner decides at the gate because the user would see it.

This is the decision `plan/milestones/M1.md` asks for beside the eleven spikes.

## Out of scope

Glyph rasterisation (S11). Applying an effect to a real component (the UI kit).

## Traps

- An effect that costs a repaint every frame at rest is worse than no effect: idle CPU is a budget.
- The notes list window-level backdrops (Mica and the like). Those blur what is behind the window; the CSS blurs what is behind an element inside it. They are not the same thing.
- A spike never writes a triage row. It drafts one in its record.
- Find each GPUI capability in the pinned source. A style method that exists may still be a no-op on the Windows renderer.
