## Outcome

Dev-only recording hooks, inert unless a variable is set in an unpackaged fake-launcher run (gated the same way as `resolveFakeLaunchersDir`):

- `FakeReport` gets an `onEvent` with one global sequence number, so cross-kind order (close, write, start) survives; the kill event keeps its tree flag; clipboard clears and login-item sets are recorded.
- One observer in `writeFilesAtomic` separates adapter writes from simulator writes.
- An optional `trace` dependency on `LaunchService`, called from `timeSteps`, `onAttention` and `finally`, records exact job transitions.
- The IPC registrar folds its three returns into one envelope and calls an optional recorder, redacting `accounts:create.password`, `accounts:setPassword.password`, `vault:setSecret.value` and the `vault:getSecret` response.

Spike notes settle three untested assumptions: whether `DOMSnapshot.captureSnapshot` and `Accessibility.getFullAXTree` work with the app's `devTools:false`; whether the browser target's `SystemInfo.getProcessInfo` returns the app's PIDs; where the built `.ico` lands.

## Out of scope

Any change that alters behaviour with the variable unset. Writing the harness (T05) or the capture kit (T07).

## Traps

- This is the only ticket that touches `src/`. The branch never merges; still, treat every line as if it could ship.
- A recorder that logs a request body can log a password. Redaction is tested with a planted value before anything is recorded.
- Never identify the app's processes by image name; the owner's installed copy may be running in the tray.
