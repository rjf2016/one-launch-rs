## Outcome

`plan/decisions/M1-S10.md`: pass, or fix the script before Milestone 6. The record lists each contract assertion with its result, the pinned `makensis` and plugin set that built the stand-in, what the stock templates do that the contract did not expect, and what F5 hardens. The stand-in is built from the templates in `oracle/takeover/nsis` as they are; its script lives in the spike.

The placeholder exe is a few lines of Rust that accept `--updated`, `--start-hidden` and `--data-dir=`, write one log line and exit.

## Out of scope

The real installer and the release workflow (Milestone 6). The rehearsal as a permanent CI job (F5). The Rust updater.

## Traps

- No installer runs on the owner's PC: not Electron's, not the stand-in, not `makensis` output of any kind. The hook refuses it; the runner is the only place.
- The stock check for a running app uses WMI (`takeover.md` step 2). The stand-in uses the image-name hook instead. Anything Riot is not involved, and stays so.
- `installed-registry.json` belongs to the oracle, which only the owner changes. The spike uploads it as an artefact; a separate pull request adds it.
- The runner's install path contains its user name. Replace it before anything is uploaded, as the oracle's scan requires.
- Whether stock StdUtils parses `--flag` is an open question in `takeover.md`. Answer it.
- The download comes from the old repo's public release. Nothing is published, tagged or signed here.
- The oracle's pin is 1.0.0-beta.3, which is `master` and has no release. What users have installed is beta.2 or older, so that is what the rehearsal takes over. If the contract differs between the two (the installer templates, the updater's arguments), the record says where; `oracle/takeover` was read from the pin.
