## Outcome

A Cargo workspace that every later ticket only fills in.

- **Members.** Every crate of `architecture.md` exists as an empty library (`ol-app` and `xtask` as binaries) with its dependencies on other members and on third-party crates declared, so the graph and the lockfile are final. One crate is new: `ol-testkit-macros`, an empty proc-macro crate with no dependency, for the `#[parity]` attribute of F6e; `architecture.md` gains its row. Twelve empty binaries `spikes/s01` to `spikes/s12` exist with the dependencies listed below; `spikes/s05` also has a library target, because `spikes/s09` depends on it and Cargo cannot link a crate that has only a binary. Spikes are not default members and no product crate depends on one.
- **`xtask`'s own dependencies.** Declared now, from the approved list, for the tickets that fill it (F6c, F6e, F7a, F7c): `serde`, `serde_json`, `regex`, `sha2`, `time`, `anyhow`. None of those tickets has a manifest in its scope.
- **README.** The table gains the workspace's folders, and "No Rust exists yet" goes.
- **Dependencies.** The approved list of `PLAN.md` is resolved into `[workspace.dependencies]` at exact versions, with the features `architecture.md` names (`serde_json` `preserve_order`, `rusqlite` bundled and backup, `ureq` on rustls). `tray-icon` and `muda` are left out; S1 decides. `Cargo.lock` is committed.
- **The GPUI pin.** `plan/decisions/M1-gpui-pin.md` records the `gpui-pre` and `gpui-kit` versions, the Zed commit that `gpui-pre` snapshots, the Rust version they need, and the licence of each crate taken. `gpui-notes.md` is corrected wherever it was wrong.
- **Toolchain.** `rust-toolchain.toml` pins one exact Rust version with rustfmt and clippy. `tools.toml` pins the versions of sccache, cargo-nextest, cargo-deny, cargo-mutants and cargo-about; CI installs prebuilt binaries at those versions.
- **Gates.** `deny.toml` bans the crates listed in `architecture.md`, allows crates.io as the only source and lists the accepted licences. `clippy.toml` holds the `disallowed-methods` of `workflow.md`. `#![forbid(unsafe_code)]` is in every crate but `ol-platform-win` and the spikes, and an `xtask` lint proves it. `cargo xtask check` runs everything a pull request must pass. `.cargo/config.toml` holds the alias that makes `cargo xtask` run the workspace's `xtask` with `--locked`, and nothing that belongs to one machine (no sccache path, no target folder).
- **CI.** `ci.yml` gains tier 0 (Linux: fmt, deny, the lints, a secret scan, the oracle manifest's hashes) and tier 1 (Windows: build and nextest of the GPUI-free crates, `--locked`). `gate` waits for both.

This is the milestone's interface ticket: the 15-file cap does not apply to the generated crate skeletons.

## Out of scope

Any code inside a crate beyond the skeleton (F2, F3, the spikes). Hooks, the owners file, test-integrity and ledger tooling (F6). CI tiers 2 and 3 (S9, F4, F5). Release profile tuning (S8).

## Traps

- `gpui-notes.md` is web research that nobody ran. Look up each crate on crates.io before pinning: name, publisher, licence, the Zed commit behind it. If `gpui-pre` is not what the notes say, or only a git dependency would work, stop and ask the owner: git sources are banned.
- `gpui-kit` pins `gpui-pre` exactly. Choose the pair together, newest pair that builds.
- The installed toolchain is stable 1.100.0. The pin is whatever the chosen GPUI needs, not whatever is installed.
- A feature added later can pull a new package into `Cargo.lock`. Declare the features the design names now; anything after this ticket is a `deps` ticket.
- Tier 0 runs on Linux. It must not compile a Windows-only crate; pure crates use `winpath`, never `std::path`.
- In `gate`, a skipped job is not a pass: use `if: always()` and test each `needs.*.result` for `success`.
- Pin every action to a commit hash.
- The app cannot push `.github/workflows/`. Commit that change last, push the rest, and leave the workflow commit for the owner (`plan/design/workflow.md` › "Acting as the app").
- `cargo install` is the orchestrator's, once, from `tools.toml`. Ticket agents never run it.
- Already installed on the owner's PC, on 2026-11-13, with rustup 1.29.3 and stable 1.100.0: cargo-nextest 0.9.152, cargo-deny 0.20.2, cargo-about 0.9.3, cargo-mutants 27.1.0, sccache 0.19.0. `tools.toml` pins these unless one fails with the pinned toolchain. cargo-about installs only with `--features cli`.
