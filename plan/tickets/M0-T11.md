## Outcome

`oracle/takeover/` holds:

- `contract.md`: the installer and updater contract as numbered, checkable assertions (arguments, mutex, registry values, uninstaller behaviour, Run value rule, relaunch), each cited to the template or source line;
- `nsis/`: the electron-builder templates and the effective defines exactly as the current build uses them, with their licence;
- `vault/portable-v10.json`: an AES-256-GCM vector in the `v10` layout with a throwaway key, for the codec;
- `vault/make-local-fixture.mjs`: writes a scratch Electron data folder with placeholder secrets, for the same-machine cross-read test (Electron writes, Rust reads, and the reverse);
- `migrations/`: schema dumps after each migration step.

## Out of scope

Running any installer on this machine. Reading the real data folder or its `Local State`.

## Traps

- DPAPI output is bound to the user and machine, so a DPAPI-wrapped key can never be a committed golden file. Only the portable vector is committed.
- The stock template's running-app check uses WMI. Record it as it ships; the replacement is a triage decision.
- electron-builder's NSIS plugins have their own licences; check them before vendoring binaries.
