## Outcome

`plan/decisions/M1-S5.md`: pass, or the fallbacks (`PrintWindow` for capture; a `Probe` wrapper that records bounds and text at prepaint if the accessibility tree lacks them). The record says where the tree comes from, how input is injected, which capture API is used and what each costs. `docs/cookbook/automation.md` holds the pattern that `ol-automation` and F4 build on.

The window and the capture live in the crate's library target, with the binary as a thin entry point: S9 depends on this crate and reuses both as they stand.

## Out of scope

The full verb set (`wait_for`, `wait_idle`, `api.invoke`, `platform.oplog`), the feature gate and the release-build check: `ol-automation`'s own tickets.

## Traps

- Input never goes through `SendInput`: it would type into whatever the owner has open. Dispatch inside GPUI or post to our own window.
- The capture must not include another window's pixels. Capturing the screen region is wrong even when it looks right.
- The notes say elements with an id appear in the AccessKit tree. Unverified: check whether bounds and text are there without a screen reader attached.
- Rounded corners and the caption-button overlay differ between captures and the oracle's shots; say how each is masked.
- The pipe name carries the pid, and the pipe exists only with `--automation`. The spike shows both.
