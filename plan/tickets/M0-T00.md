## Outcome

The branch `oracle-tooling` already exists at the pin, locally and on `origin`. Work is pushed to it directly; no pull request is ever opened from it. This ticket adds a `scripts/oracle/` folder holding:

- a shared `--out` convention: every generator writes under the given folder, defaulting to `..\one-launch-rs\oracle`;
- JSON schemas for every artefact kind in `plan/design/oracle.md` (vector file, catalogue entry, replay script, replay expectation, layout sidecar, triage linkage, manifest);
- the normaliser (aliases for ids, `<ts>` and `<ms>`, scratch roots in all four encodings, `*_enc` projection), with unit tests of its own;
- `verify.mjs`: validates every file against its schema, recomputes `MANIFEST.json` hashes, runs the secret scan over the bundle, and fails on any `C:\Users\` or other user path;
- its own vitest config, so nothing here runs under `npm run check`.

The existing `oracle/fixtures/_generator` runs from the branch (relocated or junctioned) and reproduces the seeded fixtures.

## Out of scope

Any change under `src/` (T04). Any capture (T02 onward).

## Traps

- `scripts/` is eslint-ignored and outside the main vitest include; keep it that way so `npm run check` is unaffected.
- The fixture generator resolves the repo as `../../..`; it only runs when its folder sits inside the repo.
- PNGs cannot be secret-scanned. The verify script must check sidecar text for user paths instead, and captures must run with `TEMP` on a neutral folder.
