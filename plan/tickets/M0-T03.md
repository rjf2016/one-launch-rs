## Outcome

`oracle/l1/` holds one JSON file per function: cases with byte inputs (`$file` with sha256, or `$bytes`), and either the output or the error name and message, produced by running the real TS.

Split across five agents with disjoint folders: `steam/`, `epic/`, `battlenet/`, `riot/`, `core/` (updates, redaction, paths, window guard, What's New, migrations schema dump, the IPC bad-payload matrix, renderer `lib/` helpers).

Each area also gets:

- a seeded mutation corpus for its byte-exact rewriters (loginusers rewrite, INI section rewrite, Battle.net config serialise, Riot session splice);
- adversarial cases where JS and Rust differ: Unicode classes in `\d`, `\s`, `\b`; UTF-16 length limits with astral characters; `parseInt` leniency; lone surrogates; `localeCompare` with base sensitivity.

A coverage run under the generator lists which branches of each target stay uncovered; those become more cases or a named gap in the gate report.

## Out of scope

Adapter flows and stateful services (hand-translated later; see the design). Any `src/` change.

## Traps

- Inputs are bytes, never JSON strings: BOM, CRLF and invalid UTF-8 are behaviour.
- Error cases must capture the exact message; several are shown to the user verbatim.
- Parsers have size caps and must stay linear; include a case at and just over each cap.
