## Outcome

`plan/decisions/M1-S8.md`: the numbers, and a budget per metric for the owner to accept at the gate. Proposed: clean release build under 10 minutes, core test loop under 20 s, exe under 40 MB, first frame under 300 ms, idle working set under 150 MB. Where a proposal is missed or beaten by a wide margin, the record proposes another and says why. It also proposes the `[profile.release]` settings; applying them to the root manifest is a separate ticket.

The window measured is a title strip and a grid of 500 text cards: enough to load the text system and the renderer, and no more.

## Out of scope

Changing the root manifest. Performance of real screens (the skeleton, F4, and every gate after).

## Traps

- Measure the spike's own child through the handle it got when it started it. Process tools are forbidden, and matching by image name could pick up the owner's installed app.
- "First paint" has a definition in `METHOD.md`. A number measured another way is not comparable; say so if the same way is impossible.
- Electron's baseline counts all of its processes together. The Rust figure is one process; state that beside the comparison.
- A debug build's numbers mean nothing for the budgets. Release only, and say which profile.
- This PC is fast (i9-12900K). CI build time is a separate number, taken once S9 has a job.
