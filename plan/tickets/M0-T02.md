## Outcome

`oracle/tests/catalogue.json` lists every existing test: id, file, suite path, name, environment (node or jsdom) and kind (`pure`, `stateful`, `adapter-flow`, `renderer`, `live`, `tooling`), plus a pointer to its result golden where one exists.

`oracle/tests/goldens/` holds, per adapter-flow test, the full result JSON of each `preflight`, `switchAccount`, `launchGame` and `restoreBackup` call, captured by a vitest `setupFiles` shim. A hand-ported Rust test then compares the whole result, not only what the original asserted.

A first pass marks waiver candidates (web-only and tooling tests) with a proposed category, for the owner to approve at the gate.

## Out of scope

Any `src/` change; the shim wraps from the test side. Translating tests to Rust (ticket-prep does that per ticket later).

## Traps

- Ids must survive a re-run and a rebase after a critical fix: derive them from file, suite path and name, never from position.
- The five `*-live.test.ts` files are gated by an environment variable and read real launchers. Catalogue them as `live`; do not run them.
