## Outcome

`plan/decisions/M1-S11.md`: pass, or a tolerance policy for the owner to accept (which runs may differ, by how much, and how the UI check treats them). The record names the font family and the settings that came closest (the family Chromium resolved, weight mapping, letter spacing, optical size, hinting), and says whether a difference is constant or grows with length. `docs/cookbook/text.md` holds the settings every text element uses.

## Out of scope

Glyph rasterisation and pixel comparison: pixels are not a gate. Text in the title bar's native overlay.

## Traps

- The sidecar records the family Chromium resolved (`font` in each text run), not the CSS stack. Start from that.
- A variable font has an optical-size axis that Chromium sets from the font size. If GPUI does not, small text comes out wider or narrower by a constant factor.
- Widths are fractional in both engines and rounded differently. Compare unrounded values where the sidecar has them.
- Measure through the text system the app will use, in a real window if a windowless measure differs. Say which.
- Volatile runs (times, backup names) are flagged in the sidecar. Never sample them.
