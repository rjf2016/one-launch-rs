## Outcome

`plan/decisions/M1-S9.md`: pass, or the fallback (a dedicated VM lane for UI parity, which is the owner's decision because it costs money or a machine). The record gives the runner image, the renderer the runner ended up with, the fonts found and missing, the cache layout that makes the GPUI build affordable, and the shape of tier 2.

The window and the capture are S5's, reused as they stand.

## Out of scope

Tier 2 itself (F4). Comparing a real screen against the oracle (F4).

## Traps

- A hosted runner has no GPU. Whether the DirectX path falls back to a software device, and whether DirectComposition works in the runner's session, is what this spike finds out; `GPUI_DISABLE_DIRECT_COMPOSITION` is from the notes and unverified.
- The oracle's text was measured with the fonts of the owner's Windows 11. A server image may lack them, and a missing font changes every box. Report it; do not ship a font into the repo without a licence check and the owner's word.
- "Passes on retry" is a failure here. The point is to learn whether UI parity can be a required check.
- The workflow runs on demand and on changes under `spikes/s09/`, not on every pull request.
- No self-hosted runner on the owner's PC, ever.
